# P4 完成全案逐页文案

## 本阶段目的

按已经批准的结构和校准后的语言，把每页发展成精准、丰富、完整且适合一页承载的内容。

## 内部工作节奏

按章节推进以控制上下文，但不要求用户逐章确认：

1. 读取本章页面架构、材料包和语言侧写；
2. 写完一组页面；
3. 检查判断是否连贯、内容是否重复、页面容量是否合适；
4. 回到相关原文修正；
5. 更新 `.proposal-work/proposal-draft.md`；
6. 继续下一章。

## 每页写作

一页只证明一个主要判断。先明确客户看到这页后应相信什么，再决定最合适的内容组合。

页面正文不是把 `claim`和`content_requirement`改写成长段。回到材料，把证明过程发展成客户能够直接看见的模块；Page Architecture 中的文字只是取材任务，不是需要沿用的句法。

每个内容块需要真正展开：

- 段落：写出事实、解释与含义，不只列关键词；
- 竞品/产品：写清对象、定位、卖点、内容策略、矩阵或数据中与判断有关的部分；
- 表格：完整表头、对象、单位、时间、口径和结论；
- 图表：真实数据、轴、比较关系和读图结论；
- 图片：实际图片或明确的内容要求及其证明作用；
- 模型/矩阵：维度定义、各区含义和本项目落点；
- 路线图：阶段、任务、责任、资源、节点或衡量方式；
- 案例：背景、动作、结果和对本页判断的启示。

内容类型由页面任务决定，不机械要求每页 2–4 个要点。

## 页面容量

字数只是参考，不是规则：

- 一句话、一张图或一个大数字足以证明时，可以很轻；
- 一般论证页需要足够的段落、比较或内容块；
- 数据、竞品、框架与执行页可以更丰富；
- 当一页同时承担两个判断，或信息无法形成清楚层级时拆页；
- 不得为了“适合 PPT”提前把完整论证压成摘要。

删除某段内容前问：删掉后，下游 PPT 制作者是否仍能理解这页为什么成立、需要展示什么、怎样制作？不能就保留。

## 语言自检

模型自行检查：

- 是否面向客户说话；
- 是否出现“甲方、乙方、客户要求”等幕后语言；
- 是否连续使用同一种反转句；
- 是否大量依靠连续段落和转折词组织内容，而没有形成可见模块；
- 是否把分析过程写成结论；
- 标题是否有判断但没有夸大；
- 相邻页面句式是否有变化；
- 是否有 AI 式抽象词堆叠。

完成全案后再做一次跨页语言回看：集中找出所有“不是 A，而是 B”“不只 A，更是 B”“真正的 X 是 Y”等反转句。只有确实承担一次关键认知推翻的句子才保留，其余改为正面判断、事实、因果、条件、比较、动作或结果。不要只检查相邻两页；同一套路散落在十几页中，仍然会让整份方案像分析文章。

同时回看 `project-memory.md`中的明确拒绝、禁用称谓和已经否决的表达，并在工作稿中搜索对应词。引用竞品原话或历史材料时可以保留，但本方案自己的方向、栏目、Demo 和行动建议不得重新引入用户已经否决的概念。

不要运行语言 lint。

## 工作稿格式

使用 `contracts/by-page-copy.md`。工作稿允许保留折叠给审阅和事实审计使用的内部字段；最终交付会删除这些字段。

## 完成标准

- 所有页面均已达到终稿颗粒度；
- 每页判断与结构审阅一致；
- 页面内容丰富但没有超出一页可理解容量；
- 表格、图表、图片和制作关系可被下游直接理解；
- 已准备进入最终实际使用事实审计。
