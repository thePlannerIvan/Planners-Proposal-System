# P2 为每页准备材料包

## 本阶段目的

让模型在写每页时轻松回到正确资料，不依赖模糊记忆，也不把全部原始资料重新塞进上下文。

## 工作方式

按章节处理 Page Architecture。对每页：

1. 读取页面判断与 `content_blocks`；
2. 通过 `source-index.json`找到最可能相关的原始资料；
3. 打开相关页、段落、Sheet、表格或图片上下文；
4. 同时查找支持材料和相反材料；
5. 记录可直接使用、需计算、只能做背景、仍缺失的内容；
6. 判断这些材料是否足够完成页面。

材料包只服务当前页面，不预分类全量数据。

## `.proposal-work/page-material-packs.json`

每页记录：

- `page_number`
- `claim`
- `materials[]`
  - 来源路径与定位；
  - 相关原文或数据切片；
  - 它支持或挑战什么；
  - 可用于哪个内容块；
  - 需要注意的口径；
- `content_development`
  - 每个内容块可以怎样展开；
  - 适合段落、表格、图表、图片、模型、路线图或其他形式；
- `gaps`
  - 缺什么；
  - 缺失是否影响核心判断；
  - 可否降低措辞或改变内容形式。

不需要为所有数字分配 ID，也不要把材料包变成 Evidence Ledger。

## 判断边界

- 来源否定核心页面判断：停止该页，回到 Co-creation。
- 只影响措辞强度：在 By-page 内降低结论并记录原因。
- 能用已有材料完整证明：继续写作。
- 图表需要大型数据：只提取实际需要的字段、范围或数据切片。
- 图片无法文本化：保留文件定位和需要从图片读出的具体信息。

## 完成标准

- 每页都能快速回到相关原文；
- 没有为了省事让同一份泛化材料支撑所有页面；
- 关键反例和口径问题已暴露；
- 可以选择代表性样页开始完整写作。
