# P3 代表性完整样页校准

## 本阶段目的

在写完整方案前，用少量真正写完整的页面确认语言、页面厚度和内容结构。用户通过 HTML 阅读，不在聊天中审阅长文档。

## 选择样页

根据方案实际构成选择 3–5 页功能不同的页面，例如：

- 洞察或问题重定义页；
- 数据、竞品或比较页；
- 核心策略页；
- 框架、执行或路线图页；
- 必要时包含一页章节转场。

不要为了覆盖类型选择不重要的页面。
不得只选择连续的开篇诊断页。至少包含一页数据、比较或具体对象页，以及一页策略、机制、框架或执行页；否则无法证明语言能够跨页面类型成立。

## 写到什么程度

样页必须达到终稿颗粒度：

- 观点式标题；
- 完整核心判断；
- 每个内容块都写出实际可见内容；
- 表格给出表头、单位、时间和结论；
- 图表写明真实数据关系和要表达的发现；
- 图片给出实际文件或清楚的图片需求；
- 必要的行动含义；
- 页面容量合理。

样页不是几十字的风格片段，也不是结构占位。

## 自动打开

将样页写入 `.proposal-work/sample-draft.md`后直接运行：

```bash
node "<Planners-Proposal-System 目录>/proposal-by-page-copy/scripts/start-copy-review.mjs" \
  --copy "<project>/.proposal-work/sample-draft.md" \
  --review-dir "<project>/.proposal-work/reviews/sample" \
  --kind sample \
  --port 0
```

不要询问用户要不要审阅。告诉用户保存后回到 Codex 发送“已完成”，然后结束当前回合。

## 用户反馈后

- 检查并验证反馈文件；
- 明确回复已收到；
- 先将语言、密度、可见内容结构和页面容量反馈更新到 `copy-style-profile.md`，同步改写其中已经失效的规则与示例；
- 修改样页并在必要时重新打开；
- 样页批准后继续全稿，不新增章节级人工门禁。

聊天里表示“后面会注意”不算吸收反馈。若用户指出“像分析文章”“内容太薄”“客户语气不对”等系统性问题，必须先更新语言侧写，再按新侧写重写样页。

## 完成标准

- 用户在 HTML 中看到了完整样页；
- 风格、密度、内容块展开方式和容量已经校准；
- 反馈已真实改写项目语言侧写，不再保留与反馈矛盾的旧规则；
- 可以按同一标准完成全案。
