# 中文提案页面语言

提案页不是缩短的分析文章。它是一个可以被扫读、讲述和制作的视觉化论证单元：

```text
标题给出判断
→ 内容证明判断
→ 图表或结构让关系可见
→ 解释这对客户意味着什么
→ 衔接下一页
```

## 文章与提案页的区别

| 分析文章 | 提案页面 |
|---|---|
| 用连续段落展示推理过程 | 把结论及其证明拆成可见内容模块 |
| 依赖“因此、然而、不是……而是……”连接 | 依赖标题、分组、比较、因果、流程和数据关系组织 |
| 一段话同时混合事实、判断和建议 | 让事实、判断、行动、数据、模型各自承担清楚角色 |
| 作者站在外部解释对象 | 直接面向品牌、团队和业务共同作出决定 |
| 读完全文才知道结论 | 先看到本页判断，再理解它为什么成立 |

不要把“提案语言”定义成每段几句话、每页几个要点。段落数量不能证明页面感，短句也可能只是空洞摘要。

### 改写示例

分析文章式：

> 品牌当前面临的并不是简单的声量问题，而是在内容资产层面缺少统一的人格系统，因此未来需要通过栏目化运营实现心智沉淀。

提案页式：

```text
标题：稳定栏目，才能把一次曝光积累成品牌记忆

现状
- 内容随项目临时起题，同类主题没有连续识别
- 用户记住单篇信息，难以形成对品牌的稳定预期

动作
- 建立 3 类长期栏目：产品体验、运动场景、人物故事
- 每类栏目固定识别线索、内容任务和更新节奏

结果
- 单篇内容服务当期转化
- 栏目连续性沉淀品牌认知
```

后者不一定字更少，但事实、动作和结果已经成为可以制作的页面内容。

## 先提取本项目风格

如果用户提供或项目目录存在明确参考方案，优先从用户指定材料中提取：

- 标题句式与长度倾向；
- 语气强弱、正式程度和情绪强度；
- 数据与解释的比例；
- 页面信息密度；
- 正文使用完整句还是关键词结构；
- 图表结论和跨页转场的写法；
- 常用词与禁用词。

只提取语言和页面组织规律，移除品牌名、产品名、数字、Slogan、项目结论和创意概念。不要把多个风格不同的历史方案平均混合。

必须记录参考文件的真实路径、版本和选择原因。不得无声读取其他测试目录、旧项目交付物或用户未指定的历史文件；确需借用时先说明来源及局限，避免把旧测试产物污染当前 Forward Test。

抽样时优先观察页面上真正可见的结构：标题、标签、分组、表格、图表、短段和结论怎样配合。不要只抽取 PDF 的连续文本后，误把阅读顺序还原成文章段落。

优先级：

1. 用户明确指定的优秀方案；
2. 当前客户已经采用的材料；
3. 当前 Brief 的语言；
4. 选定的历史优秀方案；
5. 本 Skill 的默认风格。

Method Wiki 主要提供论证结构和页面逻辑，不默认承担语言风格库的角色。

## 默认语言原则

- 面向客户决策，不展示模型做了多少分析。
- 标题表达判断，不使用“市场分析”“消费者洞察”等空标签。
- 数据与解释分开：先说明看到什么，再说明意味着什么。
- 用内容模块组织证明：事实、判断、动作、模型、数据、案例、结论各有位置。
- 每页只推进一个主要判断。
- 不把洞察写成口号，不用夸张动词弥补证据不足。
- 前后页保持术语一致。
- 标题可以锋利，但不得强于证据和 Human Direction。
- Production Notes 不重复 Visible Copy。

### 避免模板化反转句

“不是 A，而是 B”可以帮助建立一次关键反转，但连续使用会让所有页面听起来像同一个模型写的。

- 默认使用正面、直接的判断句。
- “不是/而是”“不只/更是”“真正的……是……”只在旧认知确实需要被推翻时使用。
- 相邻页面不要重复同一种句式；一页内不连续使用两次。
- 如果一句话可以直接写成“消费者先被脚感说服”，就不要写成“消费者不是先爱上品牌，而是先被脚感说服”。
- 用事实、因果、条件、比较、动作和结果轮换句式，不靠反转连接词制造锋利感。

在 `copy-style-profile.md` 中明确记录本项目允许偶尔使用的强调句式、需要避免的高频连接词、3–5 个正面陈述示例和相邻页面的句式变化规则。

## 页面构成建议

按当前页面任务自由选择结构，但优先让内容承担清晰角色：

- 标题：本页结论；
- 支撑内容：证明结论的必要事实或判断；
- 视觉关系：比较、递进、因果、层级、流程、矩阵或数据图表；
- 客户意义：为什么值得在此刻作出判断；
- Speaker Notes：不宜堆在页面上的解释和衔接。

不要为满足模板强行添加分论点。一个大数字、一句话或一张图能够完成页面任务时，应保持克制；但“保持克制”不等于把完整论证压成口号。需要多个事实、解释和行动含义时，应保留清楚的段落、表格或要点。

不同页面可以使用不同的可见结构：

- 数据页：关键数字、口径、比较关系、读图结论；
- 竞品页：核心判断、产品/定位/卖点、内容动作、矩阵或数据、启示；
- 策略页：选择、理由、关键动作、预期改变；
- 模型页：维度定义、各区含义、本项目落点；
- 路线图：阶段目标、任务、资源、节点和衡量；
- 案例页：背景、动作、结果、可迁移启示。

这些是判断参考，不是每页必须填写的固定模板。

## 风格校准

整份方案较长或用户提供了风格参考时，先展示 3–5 张功能不同的页面：

- 洞察页；
- 数据页；
- 策略判断页；
- 框架或执行页；
- 必要时包含章节页。

用户确认语气、密度、段落完整度和锋利程度后，再完成其余页面。校准的是语言和容量，不重新打开已经批准的 Storyline。

校准不能只选开篇诊断页。样页至少同时覆盖：

- 一页需要解释问题的页面；
- 一页由数据、比较或具体对象支撑的页面；
- 一页策略、机制、框架或执行页面。

用户反馈后，先重写 `copy-style-profile.md`中的可执行规则和正反例，再继续全案。仅在聊天中答应“以后简短一点”不算完成校准。
